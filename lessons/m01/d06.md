# M1-D6 — Static room inventory skeleton

## Today's summary

You build the HTML shell of the app Milestone 2 will make interactive.

## What this is & why you need it

Same pattern as a door schedule sheet: rows of data. Later JS will fill rows from an array; today you nail structure.

## How the session works (90 min)

Quick form recall · lesson · build room list shell · Inspect the ul/li

## Tool steps (do these in order)

1. New section or page `rooms.html` (or part of portfolio).
2. Do not wire the Add button yet.
3. Inspect to count li elements.

## The concept

Hardcoded lists are scaffolding. Structure: heading, controls (input + button), `ul` of `li` items. Milestone 2 deletes the hardcoded `li`s and draws them from data.

## Annotated example

```
<h1>Room inventory</h1>
<input id="room-name" placeholder="Room name" />
<input id="room-area" type="number" placeholder="Area m²" />
<button type="button">Add</button>
<ul>
  <li>Lobby — 45 m²</li>
  <li>Open office — 120 m²</li>
  <li>Meeting A — 18 m²</li>
</ul>
```

## Where beginners go wrong

1. Using a button that submits a form and reloads the page (`type="button"` prevents that).
2. Putting area in a way you can't later parse (keep a clear pattern).
3. Skipping the unordered list and using line breaks.
